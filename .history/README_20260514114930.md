# SEN201 Inventory and Warehouse Management System

## Project Overview
This project is a web-based **Inventory and Warehouse Management System** developed for the **SEN201 Software Engineering** course. It was adapted from an earlier business management application and refined into a simpler academic system focused on warehouse operations, stock control, goods receipt, goods dispatch, reporting, and user management.

The application is built with Laravel and uses role-based access control for super admin, admin, and salesperson users. It supports inventory item registration, category management, stock monitoring, low-stock alerts, expenses, and report generation.

## Installation Steps
1. Clone the repository and enter the project folder.
   ```bash
   git clone <repository-url>
   cd sen201-group-project-soft
   ```

2. Install backend dependencies.
   ```bash
   composer install
   ```

3. Install frontend dependencies.
   ```bash
   npm install
   ```

4. Create the environment file and generate the application key.
   ```bash
   cp .env.example .env
   php artisan key:generate
   ```

5. Configure the MySQL database in `.env`.
   ```env
   DB_CONNECTION=mysql
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_DATABASE=sen_201
   DB_USERNAME=root
   DB_PASSWORD=
   ```

6. Run the database migrations and seeders.
   ```bash
   php artisan migrate
   php artisan db:seed
   ```

7. Link storage and start the application.
   ```bash
   php artisan storage:link
   npm run dev
   php artisan serve
   ```

## Database Setup
The system uses **MySQL** and is structured through Laravel migrations in `database/migrations`.

### Main tables
- `users`
- `businesses`
- `products`
- `categories`
- `purchases`
- `purchase_histories`
- `sales`
- `expenses`
- `wallets`
- `wallet_transactions`
- `creditors`
- `creditor_transactions`
- `documents`
- `activity_logs`

### Database summary
- `products` store inventory master data such as item name, category, SKU, unit type, location, and low-stock threshold.
- `purchases` represent current warehouse stock batches.
- `purchase_histories` keep historical receipt records.
- `sales` record goods dispatch and reduce stock from the selected purchase batch.

## Authentication & User Roles
Authentication is handled with Laravel’s web authentication system. Public user registration is disabled, so users are created through the administrative workflow.

### User roles
- **Super Admin:** manages businesses, global users, reports, wallets, and system oversight.
- **Admin:** manages inventory, categories, goods receipt, goods dispatch, expenses, reports, and staff accounts.
- **Salesperson:** records goods dispatch, views available inventory, and monitors personal dispatch records.

### Access control
- Role access is enforced through custom route middleware.
- Business-based data separation is handled mainly through the `BusinessScoped` trait in controllers.

## Inventory Workflow
### System workflow summary
1. A super admin creates a business and its admin account.
2. The admin creates inventory categories and products.
3. Products are defined with SKU, storage location, unit type, and low-stock threshold.
4. Goods received are recorded through the goods receipt module.
5. The system creates a live stock record in `purchases` and a history record in `purchase_histories`.
6. Goods are dispatched from available warehouse stock by an admin or salesperson.
7. The system reduces stock and records the dispatch in `sales`.
8. Reports and dashboard statistics are updated from the recorded transactions.

## Goods Receipt & Dispatch Process
### Goods Receipt
Goods receipt is handled by the `PurchaseController`. When stock is received, the system:

- validates the selected product
- records supplier details, quantity, and cost
- creates a warehouse stock record in `purchases`
- creates a matching receipt history in `purchase_histories`
- updates the related stock and wallet records

### Goods Dispatch
Goods dispatch is handled by the `SalesController`. When stock is dispatched, the system:

- loads available inventory directly from `purchases`
- validates quantity and selling price
- creates a dispatch record in `sales`
- reduces the selected stock batch quantity

New dispatches are now made directly from inventory rather than depending on prior product assignment.

## System Architecture Summary
### Short architecture explanation
The application follows the **Laravel MVC architecture**.

- **Routes** define system entry points and user access paths.
- **Controllers** manage validation, workflow logic, and reporting.
- **Models** represent entities such as products, purchases, sales, users, and businesses.
- **Blade views** provide the user interface.
- **Middleware** controls authentication and role access.

### Module breakdown
- **Authentication Module:** login, logout, password reset, profile management
- **Inventory Module:** products, categories, SKU, storage location, stock settings
- **Goods Receipt Module:** receiving and recording stock
- **Goods Dispatch Module:** dispatching stock from inventory
- **Expense Module:** expense entry and tracking
- **Reporting Module:** inventory, sales, profit, and export reporting
- **Staff Module:** business staff creation and management
- **Admin Oversight Module:** business, wallet, and high-level monitoring
